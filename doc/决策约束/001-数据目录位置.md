## 决策结论

**保持现状。** 待办数据与配置继续存放在 `C:\Users\<用户名>\.todosimple\`，即
`Path.home() / ".todosimple"` 下，不迁移、不改为机器级共享目录。

依据：现状**已经满足**原需求"在 C 盘的固定目录下，方便同一台机器任意地方打开的 exe
都能使用同一份数据"——该路径取自 `USERPROFILE`，与 exe 所在位置完全解耦
（`storage.py:8`、`config.py:17`）。

## 约束

**必须：**
- 待办数据固定为 `Path.home() / ".todosimple" / "todos.json"`，配置固定为同目录下 `config.json`
- 路径解析必须基于用户主目录，**不得**基于进程当前工作目录或 exe 所在目录

**禁止：**
- 不得改为 `C:\ProgramData\` 等机器级/跨 Windows 账户共享目录（本项目未采用该方案）
- 不得引入依赖工作目录的相对数据路径，否则"任意位置启动共享同一份数据"会被破坏

## 理由

需求原文指向的目标已经达成，改动没有收益却有风险，故保持现状。被排除的方案：

| 被排除的选项 | 数据位置 | 排除理由 |
|---|---|---|
| B | `C:\ProgramData\TodoSimple\` | 可实现跨 Windows 账户共享，但需处理首次建目录权限（可能要求管理员）、旧数据迁移与回滚，且多账户并发写同一文件会丢数据（见下）；收益（跨账户共享）在本需求中并未被要求 |
| C | exe 同级目录 | 与需求目标**相反**：复制 exe 到另一位置会产生第二份数据，"任意位置共享同一份"被破坏 |
| D | 现状 + 环境变量覆盖 | 改动小且灵活，但当前没有"需要改数据位置"的实际场景，属于为未出现的需求预先增加配置面 |

**已知残余风险（本决策明确接受）：** 换用另一个 Windows 账户登录时，数据不跟随（各账户一份）。
`storage.py:33-41` 的存盘是"整份内存列表覆盖写"，没有跨进程锁，多实例并发写会互相覆盖。
该风险由 002-单实例决策处理，本决策不再额外引入锁机制。
