## 决策结论

**机制：Windows 命名互斥体（仅 Windows 生效）。** 用 `ctypes` 调用
`CreateMutexW`，以一个固定名字（如 `Global\TodoSimple-single-instance`）创建互斥体；
已存在则说明有实例在运行。

**提醒形态：弹框提示 + 激活已有实例并呼出遮罩。** 第二次启动时先弹一个提示框告知
「TodoSimple 已在运行」，用户确认后把已运行实例的遮罩呼出到前台，然后本进程退出。

依据：用户 2026-09-18 明确选择「仅 Windows 生效即可」与「弹框提示 + 激活已有实例并呼出遮罩」。

## 约束

> 明确写出"想让模型做的"和"不想让它做的"。约束越具体，AI 的发挥空间越可控。

**必须：**
- 互斥检查必须发生在**任何实例读写 `todos.json` 之前**（在 `main.py` 中
  `QApplication` 创建之后、`TodoStore()` 实例化之前）
- 重复启动时**必须给出可见反馈**，不得静默退出
- 激活已运行实例时，必须把该实例的遮罩呼出到前台（等价于按下全局热键的效果）
- 单实例机制**失效时必须放行启动**，不得拒绝启动 —— 宁可多开一个，不可让用户完全无法使用

**禁止：**
- 不得用「检测 `todos.json` 是否被占用」这类间接办法代替互斥（`storage.py` 的
  `os.replace` 写入不持有长期锁，检测不到）
- 不得让第二实例在退出前写入任何数据文件
- 不得引入对 WSL/Linux 生效的额外实现（用户已明确仅 Windows 即可）

## 理由

排除其他机制的原因：

| 被排除 | 理由 |
|---|---|
| Qt `QLocalServer` / `QLocalSocket` | 跨平台，但进程被强杀后残留 socket 文件，下次 `listen()` 失败，必须显式清理 stale socket。用户不要求跨平台，此复杂度无收益 |
| `QSharedMemory` | 崩溃后共享段可能残留，同样需要清理逻辑 |
| 文件锁（`msvcrt.locking` / `fcntl.flock`） | 需分平台分支；锁语义依赖 OS 在异常退出时回收 |

命名互斥体是内核对象，**随进程销毁自动释放**，不存在残留问题，也不需要任何清理逻辑 ——
这是在本决策的约束下（仅 Windows、要求失败时放行）代价最低的方案。

排除其他提醒形态的原因：

| 被排除 | 理由 |
|---|---|
| R1 静默退出 | 用户在开始菜单双击后没有任何反馈，会以为程序坏了 |
| R2 弹框后退出 | 有反馈但要多点一次才能到达界面；用户明确要求直接激活 |
| R4 托盘气泡通知 | 依赖已运行实例的托盘，通知可能被系统静音或忽略 |
| R5 直接激活不提示 | 用户不知道原本已开着一个，会困惑窗口为何突然出现 |

**本决策要解决的缺陷（现存，已核实）：** `storage.py:26` 的 `load()` 只在 `__init__`
调用一次，运行中实例从不重读文件；`storage.py:33-41` 的 `save()` 把整份内存列表覆盖写盘。
两实例并存时后存盘者胜，先存盘者的改动被静默覆盖。
