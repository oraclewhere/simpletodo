## 需求原文（用户 2026-09-18）

> 现在只有一个分页，导致有时候一个任务我需要针对某个任务创建更多的细分 todo 的时候不方便，
> 能否在任务上增加右键选项，如果右键可以创建一个关联该任务的标签页，标签页也是一个新的 todo 页面。
> 不要忘了增加个返回的能力，省的跳转到新的标签页回不去了，或者你也可以做一个树状结构，
> 点击某个任务后如果它关联的有别的标签页，就延伸出一个线连接到那个标签页。

用户当时并列了两个互斥形态（"标签页 + 返回"与"树状 + 连线"）。**已拍板选前者**，见下。

## 决策结论

| 维度 | 结论 |
|---|---|
| D1 层级深度 | **无限嵌套**：子页面里的 todo 也能继续开子页面 |
| D2 子页面数量 | **每个任务最多一个子页面**（一对一） |
| D3 导航形态 | **标签页/分页**：切换当前页面，不采用树状展开与连线 |
| D4 存储格式 | **同一份 `todos.json` 内加 `parent_id`**，无该字段即顶层 |
| D5 返回能力 | **不动 ESC**（ESC 保持"收起为右下角悬浮窗"），**新增「← 返回」按钮 + 面包屑** |
| D6 删除语义 | **级联删除**父任务及其整棵子树；**仅当该任务有子任务时弹确认框**，无子任务时保持单击 ✕ 直接删 |

依据：用户 2026-09-18 在 `/ai-dev-flow 启动` 问答中的六项选择。

### 由结论导出的结构性推论（重要，实现时依赖）

D1-b（无限嵌套）与 D2-a（每任务最多一个子页面）组合后，**每个页面有且只有一个父任务**。
因此：

- **面包屑就是一条无歧义的路径**，用一个页面栈即可表示，不需要记录"从哪条路径进来的"
- 面包屑文本可直接取各级父任务的 `text`（页面不需要独立命名 —— 这正是 D2-a 带来的简化）
- 「← 返回」= 弹出页面栈顶，回到栈中上一层

## 约束

**必须：**
- `parent_id` 缺失或为 `null` 即视为顶层 todo（保证既有数据无需迁移即可加载）
- 面包屑必须始终显示当前所在路径，且每一级可点击跳回
- 删除有子任务的任务时，**必须**先弹确认框并**在框内告知将被删除的条目数量**
- 级联删除必须覆盖整棵子树（不只是直接子项），否则会留下无法访问的孤儿数据
- 单实例机制（002）落地前，本特性的数据丢失风险显著更高，见「影响范围」

**禁止：**
- 不得采用树状展开或跨页连线（用户已选定标签页形态）
- 不得改变 ESC 的既有语义（ESC 仍是收起为右下角悬浮窗）
- 不得引入独立页面文件（用户已选定单文件 `parent_id` 方案）
- 不得删除父任务时留下 `parent_id` 指向已删任务的孤儿条目

## 理由

排除其他选项的原因：

| 维度 | 被排除项 | 理由 |
|---|---|---|
| D1 | 只允许一层（D1-a） | 用户明确选了无限嵌套；一层无法表达多层细分 |
| D2 | 每个任务多个子页面（D2-b） | 需要子页面命名、列表与逐个删除，右键菜单要多一层选择；用户只要"一个关联的标签页" |
| D3 | 树状展开/连线（N2/N3） | 用户已选标签页；且 `ui.py:130` 卡片固定 500×600，深层缩进会挤压正文宽度，连线还需自绘 |
| D4 | 独立 `pages.json`（D4-b） | `storage.py` 的 `save()` 目前只做单文件原子写（临时文件 + `os.replace`），扩展到两个文件需自行保证一致性；本需求不需要页面独立命名 |
| D4 | 加 schema 版本与迁移（D4-c） | `storage.py:21-24` 的加载过滤只看 `text` 字段，加 `parent_id` 不破坏加载，既有数据天然兼容，无需迁移步骤 |
| D5 | ESC 改为返回（R-a） | 会改变既有用户习惯（ESC 现在是收起）；用户选择不破坏它 |
| D5 | 另绑 Backspace/Alt+←（R-b） | 可发现性差，用户未必知道按什么 |
| D6 | 子项提升为顶层 | 主列表会突然冒出原本不在其中的条目，语义混乱 |
| D6 | 非空则禁止删除 | 用户要多步操作才能删掉一个任务 |
| D6 | 所有删除都加确认 | 删普通 todo 也要多点一次，比现状繁琐 |

**已明确接受的残余风险：**

1. **旧版 exe 读新文件**：旧版 `load()` 会把带 `parent_id` 的子任务**当作顶层 todo 显示**
   （不崩溃、不丢数据，但语义混乱）；旧版删除父任务时不会级联，会留下孤儿。
   无法在旧版补逻辑（旧版没有这段代码），只能接受。
2. **级联删除不可撤销**：无回收站机制，误删整棵子树即永久丢失。
   缓解手段是 D6 选定的"有子任务时弹确认框"，仅此一层保护。
