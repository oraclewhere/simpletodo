- **踩过的坑（试过但走不通的路，避免下一个人重走）**：
  - **不要再去验证"注册表写入/删除是否失败"——已实测确认正常，别重做。**
    在 Windows Python 3.10.7 上，把 `AutoStart.RUN_KEY` 指向临时子键后实测：
    `set_enabled(True)` 返回 True 并正确写入命令行；`set_enabled(False)` 返回 True
    且注册表值被删除；重复取消幂等；启用→取消往返 3 次无残留。
    **注意第一个测法有缺陷**：若目标子键**不存在**，`winreg.OpenKey` 抛
    `FileNotFoundError` 被 `except OSError` 吞掉，`set_enabled` 静默返回 False ——
    这会让人误判成"注册表操作坏了"。测试时务必先用 `CreateKeyEx` 把键建出来。
    真实 Run 键是存在的，所以真实路径不受此影响。
  - 因此"无法取消"**不是注册表操作失败**，而是下面两条：
    1. **入口不可见**：`CornerWidget` 右键菜单（`ui.py:362-367`）与托盘菜单
       （`main.py:181-186`）都只有 打开待办 / 设置快捷键… / 退出，
       自启复选框埋在「设置快捷键…」对话框里（`ui.py:438`），对话框标题只提快捷键
    2. **状态回读有缺陷**：`main.py:161` 用 `is_enabled() or config.autostart`，
       `config.autostart` 成了**只会保持 True 的回退值**。一旦注册表项失效或被外部删除，
       界面仍显示已勾选；更严重的是 `apply_autostart`（`main.py:153-156`）只在
       `set_enabled()` 返回 True 时才更新 config，所以**万一注册表写入失败，
       config 永不更新，勾选态将永久卡在 True 且用户无法取消**
  - `autostart.set_enabled` 静默吞掉所有 `OSError`（`autostart.py` 的 `except OSError: return False`），
    建议改为把失败原因暴露到界面，否则同类问题仍会以"点了没反应"的形式出现
